  <p>
    <strong>OctalFont</strong> is the home of the Octal typeface families,
    developed as part of the <a rel="noopener noreferrer" href="https://octalmesh.com">OctalMesh</a>
    design system, and of the <code>octalfont</code> tool that builds them.
    Every glyph originates as a hand-drawn sketch, gets refined as a clean
    vector, and is compiled into TTF files by a fully automated pipeline: SVG
    drawings become UFO masters, composite glyphs and OpenType features are
    generated, and <a rel="noopener noreferrer" href="https://github.com/googlefonts/gftools">gftools</a>
    builds the binaries.
    <br /><br />
    Each family is a separate repository, mounted here under <code>fonts/</code>
    as a Git submodule. The families are named after a material whose physical
    character mirrors the visual personality of the font: <em>Titan</em>,
    <em>Cuprum</em>, <em>Mercury</em>.
  </p>
</div>

<div align="center">
  <h2>Font Families</h2>
</div>

| Family            | Repository                                                            | Named after | Character                                                                |
|-------------------|-----------------------------------------------------------------------|-------------|--------------------------------------------------------------------------|
| **Octal Titan**   | [`octalfont-titan`](https://github.com/OctalMesh/octalfont-titan)     | Titanium    | Monospaced geometric display face of straight strokes and sharp corners. |
| **Octal Cuprum**  | [`octalfont-cuprum`](https://github.com/OctalMesh/octalfont-cuprum)   | Copper      | Thin, neutral, monospaced, with a weight axis (Light, Regular, Bold).    |
| **Octal Mercury** | [`octalfont-mercury`](https://github.com/OctalMesh/octalfont-mercury) | Mercury     | Rounded, fluid typeface derived from Titan.                              |

All families are released under the [SIL Open Font License 1.1](docs/licensing.md).

<div align="center">
  <h2>How It Fits Together</h2>
</div>

```mermaid
flowchart LR
    subgraph tool["OctalFont (this repository, MIT)"]
        CLI["octalfont CLI<br/>sources, check, build, package, release"]
        WF["Reusable workflows<br/>CI, release PR, publish"]
    end
    subgraph fonts["fonts/ (submodules, OFL)"]
        T["octalfont-titan"]
        C["octalfont-cuprum"]
        M["octalfont-mercury"]
    end
    CLI -- "pinned in requirements.txt" --> T & C & M
    WF -- "called by thin workflows" --> T & C & M
```

The font repositories are completely independent: each one carries its sources, its
`OFL.txt` and its history. The only thing they take from this repository is the build tool
(pinned to a release tag in their `requirements.txt`) and the shared workflow logic.

<div align="center">
  <h2>Quick Start</h2>
</div>

**Build a font** (needs Python 3.10+ and Git):

```sh
git clone https://github.com/OctalMesh/octalfont-titan && cd octalfont-titan
python -m venv .venv && . .venv/bin/activate     # Windows: .venv\Scripts\activate
pip install -r requirements.txt                  # installs the pinned octalfont[build]
octalfont check --missing                        # checks legal files, vertical metrics and glyph-set coverage
octalfont build                                  # writes fonts/ttf/*.ttf
```

**Work on the tool and the fonts together:**

```sh
git clone --recurse-submodules https://github.com/OctalMesh/OctalFont && cd OctalFont
python -m venv .venv && . .venv/bin/activate
pip install -e ".[build,test]"                   # editable install
octalfont -C fonts/titan check                   # run any command against a family
pytest                                           # the tool's tests
```

| Command                 | What it does                                                          |
|-------------------------|-----------------------------------------------------------------------|
| `octalfont sources`     | SVG -> UFO masters, composites, designspace and gftools `config.yaml` |
| `octalfont check`       | legal files, vertical metrics and glyph-set coverage against          |
| `octalfont build`       | sources + gftools builder + `meta` table; fonts land in `fonts/`      |
| `octalfont package`     | `Family-vX.YYY.zip` in the root, ready for release                    |
| `octalfont npm`         | self-hostable npm package (WOFF2 + CSS) from the built fonts          |
| `octalfont release ...` | changesets, versioning and release gates                              |

Details, options and troubleshooting: [Build Guide](docs/technical/build.md) and
[Configuration](docs/technical/configuration.md).

<div align="center">
  <h2>Use the Fonts in Your Project</h2>
</div>

<div align="justify">
  <p>
    Every font release is also published as an npm package of self-hosted WOFF2 files, split by
    script and shipped with ready-made CSS. Your project serves the font from its own origin:
    no third-party requests, no extra setup.
  </p>
</div>

| Family            | Package                                                                              |
|-------------------|--------------------------------------------------------------------------------------|
| **Octal Titan**   | [`@octalmesh/octal-titan`](https://www.npmjs.com/package/@octalmesh/octal-titan)     |
| **Octal Cuprum**  | [`@octalmesh/octal-cuprum`](https://www.npmjs.com/package/@octalmesh/octal-cuprum)   |
| **Octal Mercury** | [`@octalmesh/octal-mercury`](https://www.npmjs.com/package/@octalmesh/octal-mercury) |

```sh
npm install @octalmesh/octal-titan
```

```js
import "@octalmesh/octal-titan";   // all subsets; or "@octalmesh/octal-titan/latin.css"
```

The packages appear with the first published release of each family. The package
is a plain redistribution under the OFL: names, metadata and the license file
are unchanged, and upstream layout (`fonts/`, `OFL.txt`, the release archive)
stays the source of truth.

How packages are built and published: [RELEASING.md](RELEASING.md).

<div align="center">
  <h2>Repository Layout</h2>
</div>

```text
OctalFont/
├── src/octalfont/      the tool (sources, check, build, package, release)
│   └── data/glyphsets/ Google Fonts glyph sets shipped with the tool
├── tests/              pytest suite
├── fonts/              font families, one Git submodule each
│   ├── titan/          sources/{ai,svg,ufo}, font.yaml, OFL.txt, workflows
│   ├── cuprum/
│   └── mercury/
├── docs/               design and technical documentation
├── assets/             logos and branding
├── .changeset/         pending changesets and release configuration
├── .github/workflows/  CI, release automation and reusable workflows
└── RELEASING.md        how releases happen
```

<div align="center">
  <h2>Development</h2>
</div>

```sh
pip install -e ".[test,lint]"
pytest                            # tests
ruff check .                      # lint
octalfont release add             # describe your change (required for package changes)
```

Pull requests target `dev` and carry a **changeset**; the rest of the release is
automated by the `octal-automation` GitHub App. Read
[CONTRIBUTING.md](CONTRIBUTING.md) before you start.

<div align="center">
  <h2>Releases</h2>
</div>

<div align="justify">
  <p>
    The tool uses <a rel="noopener noreferrer" href="https://semver.org">SemVer</a>
    (<code>v0.1.0</code>); a font uses Google Fonts-style <code>MAJOR.MINOR</code>
    versions (<code>v1.001</code>). In both cases a changeset decides the bump,
    a bot-maintained draft pull request ships it, and the release is distributed
    when a maintainer publishes the draft GitHub Release. The wheel and sdist of
    the tool, and the font archives, are attached to the Releases with a
    build-provenance attestation. The whole flow is described in
    <a rel="noopener noreferrer" href="RELEASING.md">RELEASING.md</a>.
  </p>
</div>
